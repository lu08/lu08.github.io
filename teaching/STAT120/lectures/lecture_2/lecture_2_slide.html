Take a look at the Floors variable. This format is difficult to work with. To parse a text using R, you need to be very specific about the text pattern. This is done using “regular expression” (a pattern language used to search, match, and manipulate text).

df.building$Floors 

df.building <- df.building %>%
  mutate(
    Floors_num = str_extract(Floors, "^\\d+") %>%

    Floors_additional = str_extract(Floors, "(?<=\\(\\+ )\\d+") %>% 
      as.integer(),
    Floors_additional_text = str_extract(Floors, "(?<=\\d )[^(]+(?=\\))") %>% 
      str_trim()
    )

From vector to data: data frames

Data frame

In most cases, datasets in R are stored as a data frame

  • Subsetting requires two indices (row, column)
df.building[1,2] # first row, second column
[1] "Burj Khalifa"
  • Easier: each component in a data frame corresponds to a column (i.e., a variable); use $ to get the component
df.building$Name[1] # name of first building

Useful functions

names(df.building) # variable names
dim(df.building) # dimension (row, column)
nrow(df.building) # number of rows
str(df.building) # summary information
head(df.building) # first few rows
tail(df.building) # last few rows

A more general R object: list

List

  • Suppose we also want to store these information
sample.size <- nrow(df.building)
variables <- names(df.building)
  • We have the following R objects
    1. df.building: a 61 x 9 data frame
    2. sample.size: a numeric value
    3. variables: a character vector of size 9
  • Q: What if we want to store all three objects in one R object?

List

  • A: Create a list with three components
list.building <- list(data=df.building,
               sample.size=sample.size,
               variables=variables)
  • Note: if a name is not provided for a component, it will be indexed by number
  • List is very general: each component can be of different length or type
  • Use $ to extract any component
  • Try list.building$... to print out each component to double-check
  • Another way to extract component: square bracket
    • list.building["COMPONENT"] is identical to list.building$COMPONENT
  • Benefit of using $: no need to spell; use Tab
  • Benefit of using [","]: can return more than one component in a more automated fashion
TORETURN <- c('variables', 'sample.size')

R functions

R functions

  • R functions follow the same pattern: function_name(argument1 = XXX, argument2 = XXX, ...)
plot(df.building$Height_m,df.building$Floors_num) #shorter version
plot(x=df.building$Height_m,y=df.building$Floors_num) #full version
  • Use ?function_name to bring up the help menu

pipe operator (dplyr package)

The pipe operator, %>%, is a different syntax for calling R functions: FUNCTION(x) is the same as x %>% FUNCTION

vec <- c(1, 1, 5)
mean(vec)
vec %>% mean

For functions with multiple arguments: by default, R recognizes the argument being piped as the first argument; or you can use “.” to specify

# these code are equivalent
plot(df.building$Height_m,df.building$Floors_num,xlab='Height')

df.building$Height_m %>% 
  plot(df.building$Floors_num,xlab='Height')

df.building$Height_m %>% 
  plot(x=., y=df.building$Floors_num,xlab='Height')

NA values

NA values

  • NA is a special value that represents missing or unavailable entries when not in quotation marks
x <- c(3.5, 3.2, 3, NA)
length(x)
[1] 4
  • Most operations will return NA (e.g.: you don’t know the 4th value, so you cannot calculate the mean)
mean(x)
max(x)
sd(x)

Exclude NA values

To avoid the issue of getting NA’s when you perform calculations, you might want to exclude the NA values

  • Some functions give you the option to remove NA
mean(x,na.rm=T)
[1] 3.233333
max(x,na.rm=T)
[1] 3.5
  • More generally, use na.omit(x)
mean(na.omit(x))
[1] 3.233333

Check for NA values

  • Try to use R to tell you which value is NA
x
[1] 3.5 3.2 3.0  NA
x==NA  # NOT what we want!
[1] NA NA NA NA
which(x==NA)  # NOT what we want!
integer(0)
  • Instead, use is.na(x)
is.na(x)
[1] FALSE FALSE FALSE  TRUE
which(is.na(x))
[1] 4

Other types of NA values

  • NaN is also treated as NA; Inf is not treated as NA (represents infinity)
  • You should check the calculations and variable types when you see NA, NaN, or Inf
v1 <- c(1, 1, 0); v2 <- c(2, 0, 0); v1 / v2
[1] 0.5 Inf NaN
mean(v1/v2)
[1] NaN
is.na(v1/v2)
[1] FALSE FALSE  TRUE
as.numeric('4,000')
[1] NA

More on logicals

Composite logical statements

You can combine two or more logical statements together

  • ! NOT
  • & AND
  • | OR
x <- c(3.6, 2.8, 3.3, 1.2)
x>3
[1]  TRUE FALSE  TRUE FALSE
x>3 & x<3.5
[1] FALSE FALSE  TRUE FALSE
(x>3.5) | (x<2)
[1]  TRUE FALSE FALSE  TRUE

%in%

  • Recall, logical operators are the ones that return T/F
which(x < 3) # this is ok
which(x == 3)
which(x) # this is NOT ok
  • Operator %in% is another useful logical operator
subjects <- c('ENG', 'ENG', 'MAT', 'MAT', 'STAT', 'HIS')
subjects %in% c('MAT','STAT')
[1] FALSE FALSE  TRUE  TRUE  TRUE FALSE
